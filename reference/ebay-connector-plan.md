# THE PLATFORM CONNECTOR PLAN — CardOps

## 1. Owner's to-do list to unlock eBay (do in this order)

1. **Register for the eBay Developers Program** — today, no dependency. Go to https://developer.ebay.com/join → Register. Use the eBay login that owns the seller account (the account the cards sell on — the house-of-packs account, not a fresh email). Account type: Individual. The use-case field caps at 140 characters; paste: `Personal inventory app to list my own trading cards on my own eBay seller account and sync sold orders. Single seller, low volume.` **Wait: instant to ~1 business day** (occasionally a few days if flagged for manual review — answer any follow-up email promptly).
2. **Create both keysets** — at https://developer.ebay.com/my/keys create a **Sandbox** keyset and a **Production** keyset. Copy App ID (client ID), Dev ID, and Cert ID (client secret) for each into the CardOps env handoff (paste them to Beau's Claude session or directly into Vercel env vars: `EBAY_CLIENT_ID`, `EBAY_CLIENT_SECRET`, `EBAY_ENV`). The production keyset will show **"disabled"** — that is expected; step 4 fixes it.
3. **PAUSE — app dependency.** The production keyset stays disabled until the app hosts the Marketplace Account Deletion endpoint (Phase 1, item 1 below). Build ships first; this costs zero owner time.
4. **Activate the production keyset** — on https://developer.ebay.com/my/keys, next to the production keyset click the alerts/notifications link → choose "Marketplace Account Deletion" → paste the **endpoint URL** and **verification token** the app provides (will be `https://<master-ops production domain>/api/ebay/account-deletion` + a random 32-64 char token from Vercel env). Click verify; eBay sends a challenge and the keyset activates within minutes. **Wait: minutes.**
5. **Create the Redirect URI (RuName)** — dev portal → Your Account → **User Tokens** → "Get a Token from eBay via Your Application" → add a redirect URI pointing at `https://<master-ops production domain>/api/ebay/callback` → note the generated **RuName** string and paste it into env (`EBAY_RUNAME`). **Wait: instant.**
6. **Seller-account prep in Seller Hub** — confirm Business Policies are enabled: Seller Hub → Account → Business Policies (opt in at https://www.ebay.com/help/selling/business-policies/business-policies?id=4212 if not). Confirm at least one **fulfillment policy** (make one that uses eBay Standard Envelope for cards under $20, and one ground/First-Class policy for the rest), one **payment policy**, one **return policy** exist. If he already lists through Seller Hub, these almost certainly exist. **Wait: 10 minutes of clicking, no approval.**
7. **Connect** — in CardOps, click "Connect eBay" (Phase 1 UI), sign in on eBay's consent page, approve scopes. Done for 18 months.

Total owner time: under an hour. Total calendar time: gated only by step 1's approval (~1 day) and the Phase 1 deploy.

## 2. App-side build plan

**Phase 1 — OAuth connect + push one fixed-price listing with photos (~1.5-2 weeks part-time)**

1. **Account-deletion endpoint** (`src/app/api/ebay/account-deletion/route.ts`): GET handler answers the challenge — respond with `{"challengeResponse": sha256hex(challenge_code + EBAY_VERIFICATION_TOKEN + endpointURL)}`; POST handler receives deletion notices (ack 200, log, and delete any stored buyer data for that user). Ship this before anything else — the production keyset is dead without it.
2. **`ebay_connections` migration + OAuth routes** — mirror the existing `google_connections` pattern (`supabase/migrations/20260716040000_todos_calendar.sql` + `src/app/api/google/{connect,callback,disconnect}/route.ts`): new table `ebay_connections` (user_id PK, refresh_token, access_token, token_expiry, scopes, ebay_user, updated_at), RLS owner-only (`is_owner()`), same state-cookie CSRF check. Authorize URL: `https://auth.ebay.com/oauth2/authorize?client_id=...&redirect_uri=<RuName>&response_type=code&scope=https://api.ebay.com/oauth/api_scope/sell.inventory https://api.ebay.com/oauth/api_scope/sell.account https://api.ebay.com/oauth/api_scope/sell.fulfillment`. Token exchange/refresh: POST `https://api.ebay.com/identity/v1/oauth2/token` (Basic auth = client_id:cert_id). Wrap every eBay call in an auto-refresh helper in `src/lib/ebay/` (access tokens last 2 hours; refresh token 18 months). Encrypt the refresh token at the app layer (AES-GCM with an `EBAY_TOKEN_KEY` env secret) — improvement over the plaintext google_connections precedent, and this token controls the whole seller account.
3. **One-time seller setup call** (run on first connect, cache results in `service_config` or a settings row): `POST /sell/inventory/v1/location/{merchantLocationKey}` to create the inventory location (his ship-from address — publishOffer hard-fails without it); `GET /sell/account/v1/fulfillment_policy?marketplace_id=EBAY_US` (+ payment_policy, return_policy) to fetch policy IDs; `POST /sell/account/v1/program/opt_in` with `SELLING_POLICY_MANAGEMENT` if not already opted in.
4. **Listing push** ("List on eBay" button on the card page): map fields per §3 →
   - `PUT /sell/inventory/v1/inventory_item/{sku}` — SKU = `cards.sku`, quantity 1, condition + conditionDescriptors, `product.aspects`, `product.title` / `product.description` from the `listing_refs` drafts, `product.imageUrls`.
   - **Photos gotcha found in the schema**: the `card-photos` bucket is **private** (`public => false` in the init migration), so the brief's "pass Supabase public URLs" shortcut does not work as-is. Use `createSignedUrl` with a 24-48h TTL for each `card_photos` front/back/slab image — eBay copies images to EPS at listing time, so expiry after publish is fine. Fallback if eBay rejects signed URLs (query-string heavy): Media API `POST /commerce/media/v1_beta/image/create_from_file` multipart upload, use the returned EPS URL.
   - `POST /sell/inventory/v1/offer` — marketplaceId EBAY_US, format FIXED_PRICE, price = `manual_price ?? market_value`, categoryId per §3, the three policy IDs, merchantLocationKey.
   - `POST /sell/inventory/v1/offer/{offerId}/publish` — returns `listingId`.
   - Write back `listing_refs.ebay = {offer_id, listing_id, url: "https://www.ebay.com/itm/"+listingId, status: "active", listed_at}` and set `cards.status = 'listed'`, `listed_at = now()`. Flip `service_config.ebay_api` to enabled.
   - Aspect helper: `GET /commerce/taxonomy/v1/category_tree/0/get_item_aspects_for_category?category_id=...` at push time; if a required aspect is unmapped, surface a small "fill these in" form instead of failing.
5. **Verification**: sandbox for OAuth + call plumbing only (sandbox category/policy data is notoriously stale), then one real production listing on a cheap card, then end it.

**Phase 2 — order pull → auto-settle via card_sell (~3-4 days)**

1. Cron route `src/app/api/cron/ebay-orders/route.ts` on Vercel cron every 15-30 min (pattern exists: `src/app/api/cron/refresh`): `GET /sell/fulfillment/v1/order?filter=lastmodifieddate:[<last_poll>..],orderfulfillmentstatus:{NOT_STARTED|IN_PROGRESS}` — persist the poll cursor.
2. For each order line item: match `lineItems[].sku` → `cards.sku` → call `card_sell(p_card_id, 'ebay', p_sale_price, p_fees, p_ship_income, p_ship_cost, p_order_ref = orderId)`; update `listing_refs.ebay.status = 'sold'`. Single-quantity fixed-price listings end themselves on sale — no withdraw needed.
3. **Two schema fixes required (small migration):**
   - `card_sell` gates on `has_card_access()`, which reads `auth.uid()` — a service-role cron call has `auth.uid() = null` and gets `forbidden` (see `20260713170000_card_sell_rpc.sql` line 28). Amend the check to `if not (public.has_card_access() or auth.role() = 'service_role') then raise ...` (same treatment as the guard trigger at line 89, which already passes service-role through).
   - Idempotency: `card_sales.order_ref` has no uniqueness. Add `create unique index card_sales_platform_order_uq on card_sales (platform, order_ref) where order_ref is not null;` and skip-if-exists in the cron so a re-poll never double-settles (double-settling would also double-draw the basis pool — this is the one truly dangerous failure mode).
4. **Fees**: `getOrders` does not return final value fees. Settle with an estimate (13.25% + $0.30 category default into `p_fees`; `card_sales.fee_pct` exists for this) and leave `synced_to_books = false`; exact reconciliation via the Finances API is a later nice-to-have.

**Phase 3 — bulk / end / reprice sync (~1 week, after Phase 2 proves out)**

- **Bulk push**: `POST /sell/inventory/v1/bulk_create_or_replace_inventory_item` (25/call) + `bulk_create_offer` + `bulk_publish_offer` behind a multi-select "List on eBay" on the cards list.
- **End**: `POST /sell/inventory/v1/offer/{offerId}/withdraw` per card ("End listing" button; also on status change to hold/graded_out/archived).
- **Reprice**: `POST /sell/inventory/v1/bulk_update_price_quantity` (25 offers/call), wired to the existing pricing daemon (`src/app/api/cards/daemon`, `card_price_history`) so strategy-driven price changes propagate; respect `price_locked`.
- **Reconcile**: nightly `GET /sell/inventory/v1/offer?sku=...` sweep to catch listings ended/sold outside the app; scope v1 strictly to app-created listings — do NOT touch his existing Seller Hub listings (they're invisible to the Inventory API until `bulkMigrateListing`, which is a deliberate later decision).

## 3. Trading-card item-specifics mapping (cards table → eBay)

**Category routing** on `cards.sport_category`: sports values → **261328** (Sports Trading Card Singles); pokemon/mtg/riftbound → **183454** (CCG Individual Cards); other → **183050** (Non-Sport).

**Condition (both categories)** — from `condition_type`:
- `'graded'` → conditionId **2750**, conditionDescriptors: **27501** Professional Grader ← `grader` (`grader_custom` fallback; map PSA/BGS/SGC/CGC to eBay's numeric enum values fetched at runtime), **27502** Grade ← `grade`, **27503** Certification Number ← `cert_number`.
- `'raw'` → conditionId **4000**, descriptor **40001** Card Condition ← `raw_grade_estimate` (map NM/LP/MP/HP-style estimates to eBay's enum).

**Sports (261328) aspects:** Sport ← `sport_category`; Player/Athlete ← `player`; Set ← `set_name`; Year Manufactured / Season ← `year`; Card Number ← `card_number`; Team ← `team`; Parallel/Variety ← `parallel`; Language ← `language`; Autographed ← `is_auto` (Yes/No); Features ← multi-value from flags: `is_rookie` → "Rookie", `is_relic` → "Memorabilia/Patch", `serial_number is not null` → "Serial Numbered"; Card Serial Number ← `serial_number`; Print Run ← `print_run`. **Gap: Manufacturer** (required aspect) — no column; derive from `set_name` prefix (Topps/Panini/Bowman/Upper Deck lookup) with a manual override field in the push form.

**CCG (183454) aspects:** Game ← `sport_category` mapped to eBay values ("Pokémon TCG", "Magic: The Gathering", "Riftbound: League of Legends TCG"); Card Name ← `player` (CardOps stores the character/card name there for TCG cards); Set ← `set_name`; Card Number ← `card_number`; Language ← `language`; Finish ← `parallel` (Holo/Reverse Holo/Foil); Autographed ← `is_auto`. **Gap: Rarity** (required for CCG) — no column; today it would ride in `parallel` or `qualifiers`. Recommend adding a nullable `rarity text` column in the Phase 1 migration rather than overloading `parallel`.

**Cross-cutting rule:** never hardcode the full aspect/descriptor vocab — call `getItemAspectsForCategory` at push time, auto-fill what maps, prompt for required leftovers, and cache per category for a week. Title from `listing_refs` draft (enforce eBay's 80-char cap in the UI); price from `manual_price ?? market_value`.

## 4. Honest risks

- **Approval friction is real but front-loaded**: dev-account review can stall an individual account for days if the 140-char use case reads like scraping; the production keyset is dead until the deletion endpoint verifies (a challenge-hash bug means cryptic failure — test the SHA-256 concatenation order: challengeCode + token + endpointURL); RuName redirect mismatches fail silently at consent time.
- **Token custody**: the refresh token is 18 months of full seller-account control sitting in Supabase. The existing `google_connections` precedent stores tokens plaintext behind RLS; do better here — app-layer AES-GCM encryption with a Vercel env key, owner-only RLS, and never expose it through PostgREST selects. Revocation/expiry needs a visible "Reconnect eBay" state in the UI, or listings silently stop syncing at month 18.
- **Two live schema landmines found in this codebase**: (1) `card_sell` rejects service-role callers (`has_card_access()` needs `auth.uid()`), so the Phase 2 cron fails with `forbidden` until the RPC is amended; (2) no unique constraint on `card_sales(platform, order_ref)` — without one, a cron re-poll double-settles and **double-draws the basis pool**, corrupting the append-only IRS basis trail.
- **Private photo bucket**: `card-photos` is not public, so image delivery to eBay depends on signed URLs surviving eBay's fetch, with Media API upload as the fallback — budget a day for this to be annoying.
- **Sandbox is a false floor**: OAuth and request shapes verify there; business policies, category aspects, and condition descriptors are stale or broken in sandbox, so the true test is one real production listing. Accept that.
- **Fees are estimated at settle time** (getOrders omits final value fees); P/L in `card_sales` is approximate until a Finances API reconciliation pass exists — `synced_to_books` already models this.
- **Drift**: condition-descriptor enums grow as graders are added, and eBay decommissions legacy surfaces on a rolling basis — the runtime-fetch design absorbs most of this. Existing Seller Hub listings stay out of scope for v1 (unmigrated listings are invisible to the Inventory API). Marketplace-side: Authenticity Guarantee reroutes singles over ~$250 through an authenticator (shipping-flow awareness only, no app work).

## 5. Other platforms — verdicts

**Whatnot — CSV bridge now, real API when the gate opens.** The Seller API (GraphQL: product create, quantity sync, sale notifications — a near-exact fit for `card_sell`) exists but is Developer Preview and closed to new applicants as of today. Ship an "Export selected → Whatnot CSV" button instead: the `card_format_profiles` table (platform/direction/field_map/constants) was built for exactly this — seed a `whatnot_export` profile, drop signed-or-public image URLs into the image column, map Category/Condition/Shipping Profile to Whatnot's template vocab, and the owner uploads at whatnot.com/dashboard/inventory to get drafts. Register interest for API access now so CardOps is queued; until then sold-order pull is manual.

**TCGplayer — CSV only, and only if TCG singles become a real revenue line.** API keys are unobtainable (closed to new applications since late 2024, existing keys being deprecated, eBay owns it), so the only channel is the Level 4 Seller Portal CSV round-trip (Export From Live → reconcile → Import To Staged). It is also a catalog-SKU marketplace (set/number/condition/printing), not photo listings — a genuinely different data model that needs catalog-matching work. Defer until Pokemon/MTG/Riftbound volume justifies it; when it does, it is another `card_format_profiles` entry, not a connector.

**Mercari — do not build.** No US seller API exists; every cross-lister does it with browser-extension DOM automation against Mercari's listing form, which is brittle, ToS-gray, and a product in itself. If the owner wants Mercari reach, a $10-30/mo Vendoo or List Perfectly subscription beats any custom code; at most, let him hand-record a `listing_refs.mercari` entry so CardOps still tracks where a card is listed.

**COMC — a card status, not a connector.** It is mail-in consignment (they photograph, store, list — including onto eBay via their own eBay partnership); there is no seller API and nothing to integrate. If he ever sends bulk low-value cards there, model it as `zone/location_code = 'COMC'` or a status flag and nothing more.

**Cross-cutting**: standardize `listing_refs` entries as `{platform: {listing_id, url, status, listed_at, ...}}` starting with the eBay work (the sell action at `src/app/cards/[id]/sell/actions.ts` already writes per-platform keys), and name the connection table `ebay_connections` but keep the OAuth helper generic — every later platform slots into the same shape. The eBay build is the one with compounding value: eBay now sits on both sides of eBay + TCGplayer and invests in COMC.
